# Ghi chú quyết định

Quy ước: `ngày · vấn đề · quyết định · lý do`. Chỉ ghi khi spec chưa rõ hoặc phải chọn phương án.

## 2026-10-05

- **Full schema từ M0** · Data model §9 có ~26 bảng · Tạo toàn bộ entity + 1 migration `InitialCreate` ở M0, thay vì chia theo milestone · Lý do: giảm số lần chạy migration về sau; các milestone M1–M6 chỉ thêm endpoint, schema đã sẵn.
- **Concurrency token dùng `updated_at` thay vì `xmin`** · Spec §8.4 ghi "cột hệ thống `xmin` làm concurrency token" · Dùng `updated_at timestamptz` (tự cập nhật trong `SaveChanges`) làm `IsConcurrencyToken()` cho `documents`, `quizzes` · Lý do: ánh xạ cột hệ thống `xmin` trong migration EF không ổn định (PostgreSQL không cho `CREATE` cột hệ thống); hành vi 409 khi xung đột giữ nguyên, `updated_at` luôn mới nhất sau mỗi lần lưu.

- **Makefile POSIX** · Máy dev là Windows (không có `make` mặc định) · Giữ Makefile cú pháp POSIX theo spec; trên Windows chạy thẳng lệnh tương ứng (đã ghi trong README) hoặc dùng WSL · Lý do: CI và VM prod là Linux; WSL phổ biến hơn việc bundle binary make.

- **Integration test skip khi không có Docker** · Testcontainers yêu cầu Docker · Fixture kiểm tra endpoint Docker, thiếu thì ném `SkipException` · Lý do: máy dev không có Docker vẫn chạy được `dotnet test` (test QuizImport thuần vẫn chạy); CI (có Docker) chạy đầy đủ.

### M1 — Đăng nhập (2026-10-07)

- **Cookie auth challenge 302 luôn luôn → override `OnRedirectToLogin`/`OnRedirectToAccessDenied`** · Bản build .NET 8.0.31 (xác minh thực tế) `CookieAuthenticationHandler` challenge luôn trả 302 redirect, kể cả request API JSON · Override trong `Program.cs`: `OnRedirectToLogin` — request có `Accept: text/html` → 302 `/dang-nhap?returnUrl=…` (FE dùng `from` riêng nên returnUrl chỉ dự phòng); không có → `401` ProblemDetails. `OnRedirectToAccessDenied` → `403` · Lý do: SPA gọi API bằng `fetch` (credentials include) — 302 khiến fetch auto-follow về trang HTML và lỗi không đọc được; FE phân quyền bằng `GET /api/me` (401 → redirect về `/dang-nhap?from=…`).
- **`CookieSecurePolicy.SameAsRequest`** · Default `Always` đánh dấu `Secure` cho cookie → trình duyệt dev (http://localhost) và cookie jar TestServer không lưu cookie → mọi request kế tiếp 401 · Đổi `SameAsRequest`: Secure chỉ khi request https (prod qua Caddy) · Lý do: dev/test chạy http; prod luôn https nên Secure vẫn có hiệu lực.
- **Test: `WebApplicationFactory.CreateDefaultClient()` KHÔNG xử lý cookie** · `CreateDefaultClient()` tạo `HttpClient` trần — cookie jar không bao giờ gửi cookie theo request (test login nhận 200 + Set-Cookie nhưng `/me` kế tiếp 401) · `TestApp.Client` dùng `_factory.CreateClient()` (`WebApplicationFactoryClientOptions.HandleCookies = true`); client không cookie (test "logout mọi thiết bị") tạo với `HandleCookies = false` · Lý do: xác minh thực nghiệm (jar 401 vs header Cookie thủ công 200); không ghi nhận ở tài liệu MS.
- **Test DI: không có `RemoveAll<T>` khi Microsoft.Extensions.DependencyInjection 9.0.0 kéo theo** · Test project nạp MS.E.DI 9.0.0 (transit qua Microsoft.AspNetCore.Mvc.Testing 8.0.31) nhưng app chạy 8.0 → extension `RemoveAll<T>` không tồn tại ở bản runtime · Thay `services.RemoveAll<IGoogleTokenValidator>()` bằng vòng lặp `Clear()` + `Add()` từng descriptor trong `ConfigureTestServices` · Lý do: tránh thêm dependency tường minh chỉ để có 1 extension method.
- **`GET /api/public/teams` không có trong bảng API §10** · Trang `/cho-duyet` cần danh sách tổ (tên + khối) cho form "xin vào tổ" · Thêm endpoint công khai trả tổ đang hoạt động (chỉ `id, name, gradeName`) · Lý do: `/cho-duyet` là trang công (chưa vào tổ) — không thể dùng endpoint quản trị tổ; dữ liệu lộ ra tối thiểu.
- **`MeDto` thêm trường `phone`** · Spec §3.1 chỉ liệt kê `{ id, email, fullName, avatarUrl, systemRole, status, teams, requestedTeamId }` · FE form `/cho-duyet` cần tiền điền SĐT từ `me` (spec: "nhập họ tên đầy đủ & SĐT (tùy chọn)") · Lý do: 1 trường null-able, không lộ dữ liệu nhạy cảm (chính chủ xem chính mình).
- **FE định nghĩa DTO auth tay + cast `as never` cho request body** · Generator OpenAPI thủ công (M0) chỉ xuất paths + route/query params — không có `requestBody`/`components.schemas` → type sinh ra `body?: never` · `features/auth/types.ts` định nghĩa `Me`, `UpdateMeRequest`…; body gửi cast `as never` (zod vẫn validate phía client) · Lý do: giữ pipeline `gen:api` hoạt động; khi nào generator xuất schema (M3+ nếu cần) sẽ bỏ cast.

### M3 — File & tài liệu (2026-10-07)

- **Lưu file: `LocalDiskFileStorage` khi chưa có Cloudinary** · Sandbox/VM đầu không có `Cloudinary:Url` · `IFileStorage` 2 implementation; thiếu Cloudinary → file ghi đĩa (mục `Storage:Root`), phân phối qua `/api/files/{id}/…` kèm token · `CloudinaryFileStorage` giữ nguyên luồng spec §11 cho prod · Lý do: nghiệm thu M3 (upload → preview → tải về) chạy được ngay; bật Cloudinary là xong, không đổi code.
- **URL an toàn chế độ local: token DataProtection** · Không có `sign_url` của Cloudinary · Token = `IDataProtectionProvider.Protect(fileId + expiresAt)` → Base64URL, gửi làm query `t`, endpoint verify + hạn 10 phút (tải) / 10 phút (ảnh trang) · Keyring đã persist vào DB từ M1 → restart không mất link · Lý do: đơn giản nhất cho 1 instance, không lộ đường dẫn đĩa.
- **PDF/ảnh/video `Ready` ngay, không rasterize từng trang ở chế độ local** · Spec §11.2 sinh ảnh trang `pg_N` nhờ biến đổi Cloudinary · LocalDisk không có biến đổi đó → preview = chính file (PDF iframe, ảnh `<img>`, video `<video>`); `preview_pages` null (PDF) / 1 (ảnh) · Lý do: đủ dùng cho 500 user; chế độ Cloudinary vẫn giữ luồng theo spec.
- **Tìm kiếm: `search_text` + `pg_trgm` thay cho `tsvector`** · Spec §9 dùng `websearch_to_tsquery` trên `search_vector` · Thay bằng cột stored generated `search_text = f_unaccent(lower(title || ' ' || summary))` (quiz: strip HTML trước) + `ILIKE %q%` kết hợp `similarity()` để bắt gõ nhầm · Lý do: config `simple` + unaccent chất lượng ngang cho tiếng Việt, `pg_trgm` đã bắt buộc trong §9, tránh bảo trì trigger cập nhật tsvector khi sửa title/summary/HTML.
- **Endpoint multipart (upload file) cần `.DisableAntiforgery()`** · Bản build .NET 8 này áp antiforgery khung cho endpoint binding `multipart/form-data` · JSON POST không bị ảnh hưởng; CSRF của spec §3.4 vẫn là middleware `X-Requested-With: hoclieu` · Lý do: FE upload bằng `FormData` không gửi thêm header antiforgery token; bỏ antiforgery khung để giữ đúng 1 cơ chế CSRF của spec.
- **`/public/items`: truy vấn 2 loại riêng, gộp + phân trang trong bộ nhớ** · Spec §9: "Truy vấn tài liệu và quiz riêng (mỗi bên ≤ 50), gộp & sắp xếp trong bộ nhớ" · `ListPublicAsync` trả list gộp đã lọc/sắp (cả 2 loại), endpoint `Skip/Take` theo trang, `total` = số phần tử gộp · Lý do: đúng yêu cầu spec; 20.000 tài liệu / 500 user, chi phí chấp nhận được (index `ix_docs_browse` chặn phía DB).
- **Quiz "Xem nhiều" = `attempt_count`** · §9: `quizzes` không có cột `view_count` (chỉ `documents` có) · `sort=popular` với quiz dùng `attempt_count` DESC · Lý do: chỉ số tương tác có sẵn trong schema; không thêm cột mới chỉ để khớp chữ "xem nhiều".

- **C# pattern precedence: `not` bind chặt hơn `and`** · `x is not >= 1 and <= 37` parse thành `(x is not >= 1) and (x <= 37)` → `x = null` lọt qua (operand phải = false) · Bug thực: rule "tuần bắt buộc" của chuyên mục BT cuối tuần không bao giờ kích hoạt · Sửa: luôn viết `x is not (>= 1 and <= 37)` · Lý do: xác minh thực nghiệm (probe test DB thật: section `require_week=true` mà POST thiếu tuần vẫn 201); grammar pattern C# xếp `unary-pattern (not)` cao hơn `binary-pattern (and)`.
